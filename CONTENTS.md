## 10. Hypotheses and evidence boundaries

| Hypothesis | Focus |
|---|---|
| OCSH-001 | Classical deductive preservation in a restricted fragment |
| OCSH-002 | ODK reuse without kernel changes |
| OCSH-003 | Reduced adaptation costs with contract-based plugins |
| OCSH-004 | In-situ feedback and traceability gains |
| OCSH-005 | Single and composite WE-native CDE transitions |
| OCSH-006 | Safer cross-granularity inference |
| OCSH-007 | SQL-to-WE semantic and security preservation |
| OCSH-008 | Validated cross-domain capability relay |
| OCSH-009 | Gains on untargeted tasks |
| OCSH-010 | Sustained capability/question growth; scaling remains unproven |
| OCSH-011 | Improved AI-generated-code governance |

All eleven remain **E0 / proposed** in this release track. The [hypothesis registry](research-trace/HYPOTHESIS-REGISTRY.md) is the authoritative place to record evidence and status changes. In particular: valid logical entailment is not empirical truth; metric similarity is not identity; ODK differential is not a CDE state-changing delta; a proposed state is not an authorized action; and a successful relay is not proof of sustained scaling.
